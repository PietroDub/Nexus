Referência

Graph, GraphView, GraphViewLayout

O grafo é o conhecimento; a geometria vive na view. Fontes: GLOSSARY, data-model, ADR 0001.

Quem cria a primeira linha

TabelaPrimeira linhaAPI própria
graphs POST /workspaces (nested write) GET, PATCH name. Sem POST, sem DELETE.
graph_views A mesma transação: view Default, isDefault: true Ainda falta: list/create/patch/delete
graph_view_layouts Nenhuma. Só no drag da view corrente. Ainda falta: PUT /views/:id/layouts (upsert)

Contratos HTTP

RotaBody / queryEstado
GET /graphs?workspaceId= query opcional feito
GET /graphs/:id — feito. Sem nodes, sem x,y.
PATCH /graphs/:id { name? } feito
GET /views?graphId= query falta
GET /views/:id — falta. Metadados + layouts visíveis.
POST /views { graphId, name, createdBy } falta. isDefault: false.
PATCH /views/:id { name?, viewport?, filters?, isDefault? } falta. Default na mesma transação.
DELETE /views/:id — falta. Recusa última view.
PUT /views/:id/layouts [{ nodeId, x, y }] falta. Upsert PK (viewId, nodeId).

FKs

workspace 1 ──< graph 1 ──< graph_view 1 ──< graph_view_layout
                              node 1 ────────────^

Layout aponta para dois pais: a view e o node. Invariante de aplicação: node.graphId === view.graphId.

O que não fazer

  • POST /graphs — o workspace já cria.
  • x,y em nodes — ADR 0001.
  • CRUD de layout com id próprio.
  • Escrever layout no NodeService.create.
  • Incrementar node.version no drag.
